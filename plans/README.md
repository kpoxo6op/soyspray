## Findings considered and rejected

- Split three.js and the meshes out of the assembly guide's single `app.js`: rejected. The guide is designed
  and tested to work from `file://` with no network requests (`test/bundle.test.mjs`); with gzip and
  `immutable` caching from plan 002 the single file costs about 340 KB once.
- Quantise the assembly meshes: rejected. Measured gain is 128 KB to 113 KB after gzip, not worth a new
  decoder path.
- Turn on compression at the cluster ingress instead of in each image: rejected. It changes every site behind
  the ingress and spends ingress CPU on each request; precompressed files in the image cost nothing at run time.
- Merge the assembly guide's device sub-meshes and share rest materials to cut draw calls (862 at the full
  rack): deferred, not rejected. It is a large refactor of `devices.js` and `scene.js`; measure on a phone
  after 001 to 005 land and plan it then if frames are still slow.
- Pearl: redraw only when something changed and update the shadow map only when the bench changed: deferred.
  After 001 Pearl draws once per frame; the remaining gain is small next to that.
- A shared explainer kit for player, loop, stage and budgets (the two apps are separate copies today):
  deferred as a direction. It needs a decision about build contexts; `loop.js` from 001 and the audit scripts
  are written so they can move there unchanged.
